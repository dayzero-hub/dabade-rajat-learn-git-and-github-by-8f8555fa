# Rajat Dabade

I'm a developer learning the professional git workflow — branch, commit, pull request, review, merge — by shipping this starter project the way a real team would.

## What I'm learning

- How a pull request tracks a branch, not a single commit — so pushing again updates the open PR in place instead of needing a new one.
- Why branching from an up-to-date main matters — pulling first is what avoids the needless merge conflict a stale branch creates.
